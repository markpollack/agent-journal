# Verification fixtures: native stream plus the package Journal persisted from it

Each directory is one labelled good case for `ClaudeStreamVerifier`: the native Claude Code `stream-json` output
(`stream.jsonl`, the oracle) and the run package the production recorder persisted from it (`journal/`, the
candidate: a `JsonFileStorage` root with the root run and its child runs). The verifier reads both with its own
neutral parser; nothing here is interpreted by production code at check time.

| Fixture | Stream | Exercises |
|---|---|---|
| `single-result-parallel-calls` | CLI 2.1.299, sha256 `253262422d1640f2a8b23e6d049b9077e4d013143829583b3114fc4ea003ed41` | three string tool results, parallel calls, no sub-agent |
| `foreground-subagent-one-result` | CLI 2.1.299, sha256 `bf6177b0d1369d16ad4ac2e770bfe6a2920134ef09875dd355bc06ad6c9748fe` | two structured (array) results on the main thread, a foreground sub-agent with a `Read` whose input holds the integer `1` |
| `background-subagent-two-results-a` | CLI 2.1.299, sha256 `4fded346468e90e070f75212c7c61d6cc2d8edd0eed235563eafb9ef4eb9b08a` | a backgrounded sub-agent, two `init` and two `result` lines in one invocation |

The streams are byte-identical copies of `claude-code-capture/src/test/resources/fixtures/real-streams/<fixture>/stream.jsonl`
(sanitized as described there; synthetic prompts and files, identifiers replaced). Every stream carries one
`rate_limit_event` line, which the released `claude-code-sdk` drops before Journal sees it.

Candidates were generated by `VerificationFixtureGeneratorTest` in `claude-code-capture`
(`-Dverify.generate.out=<dir>`) at producer `agent-journal` `9fb921c` (producerVersion `1.12.0-SNAPSHOT`,
events schema version 1), with the session archive off because the fixtures carry no transcript. Regenerate them
whenever the producer changes what it persists, and update this note with the producer commit.

Known outcomes on these candidates, pinned by `ClaudeStreamVerifierFixtureTest` as expected defects (a regression
test passing on them does not make the property a conformance pass):

- `tool_calls.result_structured` DEFECTIVE on the main thread where a result's content is an array: the producer
  stores Java's collection rendering (Stage 13 review R13-04).
- `tool_calls.input_representation` REPRESENTATION_DIFFERS on the sub-agent's `Read`: `"limit":1` is persisted as
  `1.0` (R13-09); the value is equal, the spelling is not.
- `source_records.invocation_reference` DEFECTIVE on child runs: their records carry `invocation: -1` because the
  recorder writes sub-agent runs before it registers the invocation (R13-10).
- `tool_timing.declared` DEFECTIVE on child runs with a tool result: no `tool_timing` event states the duration's
  source on child runs (R13-11); the duration value itself equals the stream's timestamp difference.
- `dropped_lines.rate_limit_event` UNSUPPORTED: declared as a known gap of the live stream, not verified.
