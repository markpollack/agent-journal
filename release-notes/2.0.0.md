# Agent Journal 2.0.0

Agent Journal records an agent CLI's execution as durable local data: the messages, tool activity, reported usage and
cost of a run, written as one portable `events.jsonl` on the OCSF 1.9.0 schema with Journal's `agentic_cli`
extension, and checks it against the native input with an independent oracle.

2.0.0 is a new line. It shares no format or API with the 1.x line (`journal-core`, last release 1.11.0), which stays
on branch `1.x`.

## Formats

2.0.0 writes and reads only the 1.0.0 formats:

| Identifier | Value |
|---|---|
| Package kind | `agent-journal/ocsf-package` |
| Layout | `1.0.0` (standalone `events.jsonl`); `1.1.0` with a terminal binding (an archive sealed by `TerminalReceiver`) |
| Extension | `agentic_cli` 1.0.0, uid 901 (provisional, not registered with OCSF); compiled schema sha256 `e4f20236…` |
| Semantic contract, final assembly, mapping contracts, assembly profiles | 1.0.0 |

A package written before 2.0.0 names other identifiers and is refused as an unsupported format
(`UNSUPPORTED_PACKAGE_KIND`, `UNSUPPORTED_PACKAGE_VERSION`, `UNSUPPORTED_EXTENSION_VERSION`, or `UNSUPPORTED_FORMAT`
for an event file without a format declaration); each refusal names the identifier it found. Read such a recording
with the Journal version it was written with.

## Artifacts

Group `io.github.markpollack`, version `2.0.0`, Java 17 bytecode:

- `journal-ocsf-writer`: captures a CLI (launching it, reading its standard output, or replaying a recording) and
  writes the run package; `CliCapture`, `OcsfRunWriter` and `TerminalReceiver` are its API, `OcsfWriterTool` its
  command line. Runtime dependencies: the JDK and `jackson-core`.
- `journal-capture-tck`: reads a package (`PackageReader`), computes the declared analysis views and judges a package
  against its native input with the independent oracle; `OcsfReaderTool` is its command line. Consumers that only
  read packages need this artifact alone.

## What is recorded

Per CLI and launch route, as listed in the compatibility registry (`compatibility.json` in `journal-ocsf-writer`).
Input that matches no entry is retained whole, flagged untested and not normalized.

- Admitted (the CLI's raw standard output, launched and read by `CliCapture`): Claude Code 2.1.304 `stream-json`;
  Codex CLI 0.160.1 `exec` JSON stream; Antigravity CLI 1.4.6 headless `stream-json`.
- Experimental: Claude Code 2.1.299, 2.1.303 and 2.1.304 session transcripts; GitHub Copilot CLI 1.0.100 stdout
  events, session events, OTel file and usage report; Junie 3813.7 stdout, session events and session summary;
  Codex CLI 0.160.1 rollout files; the version-neutral Claude Code SDK stdio and session-file route (tested on 2.1.316
  and 2.1.319); the version-neutral Codex CLI exec stream and rollout route (tested on 0.166.0).
- Terminal profiles (packages sealed by `TerminalReceiver` from an Agent Client delivery):
  `client-terminal-claude-sdk/1` and `client-terminal-codex-exec/1` for one-shot runs, with the retained Claude and
  Codex profiles; `client-terminal-junie-acp/1` for a fresh Junie 3813.7 ACP one-shot session (its session summary
  and session events). The versioned names of the same profiles (for example `client-terminal-claude-2.1.316/1` and
  `client-terminal-codex-0.166.0/1`) are also accepted, for recordings of that one CLI version.

The [README](../README.md#what-200-records) lists the known limits of each route.

## Changes in this release

- Final format identifiers, listed above. Packages no longer carry a `non_production` flag.
- The reader reads only the 1.0.0 formats. Removed with the earlier formats: the two-file `run.json` layouts, bounded
  admission (`admit_response_uid`), the earlier Codex assembly profile, the version gates for earlier extensions,
  and the retired Claude Code `sdk` route.
- Retained terminal profiles: Claude Code fresh-start generations are qualified under the native profile and Codex
  retained threads under the ordinary profile; the earlier frozen profiles are removed.
- Junie ACP one-shot qualification: `AcquisitionQualifier.forProfile` resolves `junie-<version>-acp-session-files` to
  `JunieAcquisition`, which qualifies one fresh synchronous Junie ACP session's `summary.json` and `events.jsonl`
  against [the contract](../docs/junie-acquisition.md) and refuses a missing source, more than one candidate native
  session, an identity mismatch with the ACP session, incomplete events, changed bytes and credential-shaped
  environment variable names. Only 3813.7 qualifies; any other version is refused. Reported cost and token counts
  are taken as reported: a cost of 0 is kept, and a count the source omits stays absent. `TerminalReceiver` seals
  the qualified acquisition under `client-terminal-junie-acp/1`.
- Oracle fix: when a source writes the same execution-singleton observation twice (a live Junie session writes the
  main agent's final result block in progress and completed), the independent oracle no longer reports the two
  ambiguous observations as `DEFECTIVE` for sharing the identity they repeat. They may share it with each other
  only, and their relation class is checked.
- Verify reports and qualified acquisition manifests are byte-stable across JVMs (fixed member order).
- The extension source and its pinned toolchain live under `schema/ocsf/`.

## Build and test dependencies

Built with Java 21; Agent Judge 1.0.0 is used in test scope only. No snapshot dependency.
